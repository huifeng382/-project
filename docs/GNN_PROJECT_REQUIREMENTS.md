> 本文件是 GNN 项目（含 NetlistOpt / Rust 集成、数据、文档、脚本）的**最高优先级要求文件**。
> **任何在本项目下开启的新对话**：只要用户输入触发文本（§3）、或提及「要求文件 / REQUIREMENTS / 项目要求 / 版本号」，
> **必须先读取本文件并严格遵守全部条款**。本文件未覆盖之处，遵循 `docs/PROJECT_LOG.md`（15.2.5 文件归类等）与 `docs/GIT_PUSH.md`（推送方法）。

## 1. git 提交 / GitHub 推送的版本号命名规范（强制）

- 版本号格式：**大版本.小版本.更小版本**，如 `15.2.16`。
- **每次提交 = 一个新版本**：提交后版本号必须往后递推；commit message = **版本号 + 简短文字描述**（一句话说明改动，不要过长），如：
  `git commit -m "15.2.19 - 更新触发文本示例"`。
- 递推规则（按本次改动的**最高级别**递推）：

| 级别 | 版本号递推 | 触发条件 |
|---|---|---|
| **大版本**（major） | 大版本号 +1，小/更小清零（如 10.1.0 → **11.0.0**） | 代码**大幅度**修改；**数据**有改动；代码修改带来了**大幅度的改善** |
| **小版本**（minor） | 小版本号 +1，更小清零（如 10.1.0 → **10.2.0**） | 代码**小幅度**修改；小幅度**加入新的代码文件** |
| **更小版本**（patch） | 更小版本号 +1（如 10.1.0 → **10.1.1**） | 加入**临时文件**；**修改 bug**；**修改文本文件**（含本文档） |

- 一次提交同时含多级改动时，取最高级别递推。
- **版本号延续 GitHub 既有编号（不重新起算；`10.0.0` 仅是格式举例）**：
  最近一个按本规范命名的提交 = **`15.2.16`**（commit `f8064ce`，2026-08-26，已推送 GitHub）。
  **下一提交从 `15.2.17` 起**，按上表递推规则递增；当前版本以 §5 版本记录最新行为准。
- 注：2026-08-26 曾有 3 个未按版本号命名的过渡提交（`864b6e4` feat / `3b7727d` chore / `70d34a0` docs，均已推送），**不计入编号**；自 15.2.17 起严格执行。
- 推送方法：`docs/GIT_PUSH.md`（`-c http.sslBackend=openssl` + 凭据管理器 + 沙箱提升）。

## 3. 触发文本（记入要求模式）

- **触发文本（输入这一句即可）：「记入要求文件 GNN_PROJECT_REQUIREMENTS.md」**
  - 短形式（等价）：「记入要求文件」/「写入要求文件」/「记入要求」。
- 用户输入触发文本后：**用户之后所说的话，凡属于要求/规范/约束/长期决策类的，一律追加写入本文件**（`docs/GNN_PROJECT_REQUIREMENTS.md`），
  按 §1 以 patch 级别提交（如 `15.2.x+1 - 要求更新: ...`），并在回复中回显确认已记录。
- **新对话中只要出现触发文本，立即进入本模式**，无需其它解释。

## 4. 长期规则汇总（引用，避免重复）

- **文件归类**：文档 → `docs/`；诊断脚本 → `scripts/diag/`；报告 → `reports/`；根目录不留散文件（`PROJECT_LOG.md` 15.2.5）。
- **数据合规记录**：版本记录式（`docs/DATA_SPEC_V2_ISSUES.md`，V1.0~V3.1 等）。
- **Rust 集成记录**：`docs/GNN_RUST_DATA_DIFF.md` 第十节（10.1~10.8）。
- **推送方法**：`docs/GIT_PUSH.md`。
- **记录风格**：凡问题清单/要求类文档，优先采用「版本记录式」（版本/日期/状态/摘要表）。

## 5. 行为约束（对 AI 助手，强制）

- **方案先行，先问后改**：每次对某个问题给出解决方案时，**先给出方案（含改动清单/预期影响），不要自动执行修改**，等待用户明确同意后再动手。
- 例外：用户已明确指示执行的操作（如「直接跑」「修改」），或纯只读操作（查询、分析、读取），不在此限。
- 若方案涉及代码/文件改动、重跑实验、提交推送，一律先列清单询问。
- **长任务汇报规则**：用 SSH 启动测试/训练后，若预计等待 **>30 分钟**，**不要定期汇报进度**——只需确认程序已启动运行，并**附上检查命令**让用户自查；仅在任务完成时汇报结果。
