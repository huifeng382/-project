## 0. 怎么读这份文档（三条口径，混用会得出相反结论）

| # | 口径 | 读错会怎样 |
|---|---|---|
| ① | **名义口径 vs 可分设计口径**。V3 组内有大量重复候选（P0-1），「交付 15 个变体」与「15 个**互不相同**的变体」是两回事。凡引用组大小、行数、形状配额，必须写明是哪一档 | 会把「名义达标、实际不达标」读成达标（形状配额从 6/18 恶化到 **17/18** 就是这么差出来的） |
| ② | **行口径 vs 电路口径**。大形状每电路行数多（(9,6) 84 行/电路 vs (2,1) 4 行/电路），所以同一个比例两个口径能差一个量级 | 会把「分布严重偏斜」读成「还算均衡」（`DIFF §18.5`） |
| ③ | **抽样 vs 全量**。本文的列常量性/行数/重复率是**全量精确**（parquet 行组统计 + 逐电路聚合）；JSON 内层字段是**等距抽样**（每片 400 行，共 12,408 行 / 324 万条晶体管条目）。抽样结论一律标样本量 | 见文末「自查记录①」：头部抽样与等距抽样在同一列上差过 **50 个百分点** |

**判定图例**

| 标记 | 含义 |
|---|---|
| 🔴 **必须修改** | 不改会让后续训练结果、归因结论或交付验收**系统性失真**；下一版必须修掉 |
| 🟠 **应当修改** | 影响面较窄，或代价明显，但预期收益明确 |
| 🔶 **可绕·不许绕** | **我方改代码能让流程跑过去，但数据本身仍不达标 / 信息变少。** 必须生成方改数据，不许用代码掩盖（判入规则第 2 条） |
| 🟡 **待复核（重出前必须有答案）** | 现证据不足；**但下一版重出前必须定论** —— 不定论，新版会原样重复同一个问题 |
| ⚙️ **非必改** | 不影响生成：已核验无问题（要生成方"别改"），或纯我方侧脚本/流程 → 见 §5 |

## P0-1 🔴 必须修改：组内重复候选（V3 引入的回归）

### 现象

同一个 expr 组内，**大量候选是同一个设计的完全副本** —— 不只是「长得像」，
而是静态输入全签名与**每一列时序数据**都逐字节相同。举例（`R00088`，名义 15 个变体）：

| 设计（netlist md5） | 晶体管数 | 副本数 |
|---|---|---|
| `8054c86a` | 30 | **11** |
| `410da567` | 28 | 1 |
| `e6a518c3` | 26 | 3 |

⇒ 这一组名义 15 个变体，**实际只有 3 个互不相同的设计**。

### 证据（全量精确）

| 指标 | 数值 | 说明 |
|---|---|---|
| 孪生簇 | **2,312** 个 | 组内「静态全签名相同」的簇 |
| **涉及电路** | **6,941 / 12,455 = 55.7%** | 有同组孪生的电路 |
| **纯冗余副本** | 4,629 = **37.2%** | = 涉及电路 − 簇代表数 |
| netlist 文本级重复 | 5,018 = 40.3% | 只按 netlist 判等 |
| 受影响的组 | **798 / 837 = 95.3%** | 组大小 10~15 的组里 95% 有重复 |
| **真重复率（下界修正）** | **40.3%**（5,018） | 37.2% 是**下界**，见下 |
| 相邻步**恰好为 0** | **55.66%**（11,618 个相邻对） | 组内延迟差为零 ⇒ 与重复率吻合 |

**「完全副本」是实测的，不是推断**：抽 60 个孪生簇（136 电路 / 1,496 行），
比对**全部** arcs 列（`switching_pin`/`direction`/`output`/`vector`/`DELAY`/
`gate_states_json`/`pin_slew_json`/`pin_load_json`/`transistor_wave_json`）：
**60/60 簇内完整签名完全一致**（0 簇含 ≥2 种完整签名）。
⇒ 连波形数据（喂给 GNN 的节点特征来源）都一模一样，模型输入**逐位相同**。

**V2 对照（判「是不是这条线一直如此」）**：

| 数据集 | 组内 netlist 重复 | 组内全签名重复 | 平均有效候选数 |
|---|---|---|---|
| **V3** | **40.3%** | **37.2%** | **9.35**（名义 14.88） |
| `batch_v2_full` | 0.4% | 0.4% | 14.93 |
| `batch_v2_rest` | 0.2% | 0.2% | 11.65 |
| `batch_v2_m4` | 4.7% | 2.0% | 11.76 |

⇒ **相差两个数量级，是 V3 引入的回归，不是这条数据线的固有形状。**

### 影响（五处，全部是「读数被污染」型）

1. **有效语料缩水 37%**：可分设计 7,826/12,455 = **62.8%**；有效行
   **354,022 / 599,976 = 59.0%**。名义「~60 万行」实际只有 ~35 万行新信息。
2. **组大小判据名义成立、实际不成立**：规格要求每组 ≥10 变体，名义 803/837 组达 15；
   去重后**平均 9.35**，**466/837 组（55.7%）低于 10**（最少的一组只剩 **2** 个设计）。
3. **形状配额从 6/18 恶化到 17/18**（见 P0-2）——同一件事的另一个切面。
4. **组内延迟差（缺陷 4）的读数被重复主导**：`<1%` 档 67.3% 里 **55.7pp 是恰好 0**
   （见 P1-2）。**规格判据②「相邻差 1-5% 占 25-45%」在去重后是 26.4% —— 落区**；
   不去重读成 15.9% —— 出区。⇒ 这一条不改口径就是**误判**。
5. **排序指标口径与部署侧不可比**：组内多个完全相同的候选会把
   「选中真最优」的概率抬高（选到任一副本都算对），训练指标因此**偏乐观**，
   与 Rust 侧真实候选集（是否也有重复**待核实**）不是同一把尺子。

### ⚠ 关键约束：**删重复不是免费的**（`_t_v3_dedup_budget.py` 实测）

最直觉的修法是「把重复行删掉」。实测不可行 —— 会撞上训练侧的组大小过滤
（`src/train_sweep.py:417-420`，口径 = `groupby('expr')['circuit_id'].nunique() ≥ MIN_GROUP_SIZE`，
默认 10）：

| 口径 | 电路 | 组 | 行 |
|---|---|---|---|
| ① 交付原样 | 12,455 | 837 | 599,976 |
| ② 只删重复 | 7,826 | 837 | 354,022 |
| ③ 去重 **+ 套 MIN_GROUP≥10** | **4,359** | **371** | **157,480** |

## P0-3 🔴 必须修改 + 🔶 可绕·不许绕：`struct_prior` 三列中两列死亡

> 用户点名的那一条：「3 列中有 2 列全为 0」。**精确读数**如下 ——

### 现象与证据

## 3. 自查记录（写下来防复踩）

1. **头部抽样偏差（本次最贵的一个错）**：初版对每个分片取 `head(N)` 行做 JSON 字段统计，
   得出 `ids_avg` 零占比 **57.5%**；改成**整片等距抽样**后是 **54.7%**，

2. **扇出按「生产者」算 ⇒ 恒为 1**：`len(prod[net])` 是驱动者数（良构网表恒 1），
   正确口径是**消费者数**。初版据此得出「弱驱动判据 100% 通过」——近于恒真（P2-6）。
3. **两个「重复」口径必须分清**：`37.2%` = **纯冗余副本数 / 总电路**；
   `55.7%` = **有同组孪生的电路数 / 总电路**。两者差一个「簇代表数」（6,941 − 2,312 = 4,629）。
   混用会让「相邻步恰好 0 = 55.7%」看着与「重复 37.2%」对不上。
4. **spread 分母 `/min` vs `/median`**：同一批数据两把尺能差 2.5pp（P2-3）。
5. **绝对容差不能用在跨电路的真值比较上**：真值量级 ~1.2e-11 时，
   `EPS=1e-12` 的绝对容差等于没有容差。跨电路比较一律用**相对**容差。
6. **判据带限定语时必须按限定语取数**：见 P2-2 末（全局 2.69% vs Tier B 内 0.0%）。

### A. 数据完整性

**1. 🔴 组内设计级去重 + 补回新设计**（P0-1）—— 唯一一个**同时**污染形状配额、有效样本量、
组内延迟差、排序指标口径的缺陷。
- 去重键 = `gate_level_netlist + cell_types_json + input/output_pins_json + pin_loads_json +
  parasitic_caps_json`（**不含 `transistor_count`**，理由见 P0-1）。
- ⚠ **只删不补不行**：删完套上训练默认的组大小过滤，组只剩 371/837、行只剩 26.2%。
  必须同时补 **≥1,193** 个新设计（每组回到 ≥10 个不同设计；回到名义 15/组需 ~4,729 个）。

**2. 🔴 补齐形状配额 + 把分布从「大+深+多输出」一个角拉开**（P0-2 + P2-1）
- **(1,1) 从 0 补到 ≥300**（完全缺失，属结构性 OOD，不是数量不足）；
- 5 个单输出形状（2x1/3x1/5x1/8x1/16x1）补到配额线以上；
- 9x6 现在 **14.5×** 超额（去重后仍 8.0×）—— 用第 1 条省下的预算；
- **按行口径**把浅/小占比从 3.7%~8.1% 抬起来（行才是训练样本单位）。

**3. 🟠 `transistor_count` 的定义与来源**（P1-1）：保证同 netlist ⇒ 同值；
或明确它到底是哪个量（现在的口径与 netlist、与 wave 条目数**都对不上**）。
它同时是输入特征与 `struct_prior[0]`，且**无归一化**。
